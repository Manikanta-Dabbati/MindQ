# MindQ AI Documentation

## Provider Architecture

```text
McqGeneratorService
        ↓
     AiService
        ↓
    AIProvider
        ↓
   GroqProvider
        ↓
Groq API
```

The abstraction allows future AI providers to be added without tightly coupling MCQ business logic to a specific provider.

## Models

- GPT-OSS 20B — Fast
- Qwen 3.6 27B — Balanced
- GPT-OSS 120B — Deep Think
- Auto — MindQ recommended selection

## MCQ Pipeline

```text
User Input
 ↓
Validation
 ↓
Material / Topic Resolution
 ↓
Prompt Construction
 ↓
Groq Request
 ↓
JSON Response
 ↓
Validation / Parsing
 ↓
Persist MCQ Set
 ↓
Generation History
 ↓
Quiz
```

## Validation

The parser verifies:

- valid structured response
- requested question count
- four options
- A/B/C/D ordering
- one correct answer
- required explanation
- valid difficulty

## Limits

- maximum 20 questions in the current MCQ flow
- difficulty: Easy / Medium / Hard
- source: topic, uploaded document or Vault material

## Failure Handling

Generation includes retry handling and AI error reporting.

Provider keys remain server-side and are never exposed to the React frontend.
